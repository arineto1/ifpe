Questão 01 Tríade Fundamental da Web

Considere as seguintes afirmações sobre a tríade fundamental do desenvolvimento de aplicações web client-side (HTML, CSS e JavaScript) e seus respectivos papéis na construção de interfaces gráficas:

  • I -O HTML (HyperText Markup Language) provê a semântica estrutural básica e o delineamento dos nós de conteúdo do documento, atuando como o esqueleto composicional da página.
  • II -O CSS (Cascading Style Sheets) gerencia a apresentação visual, as regras de diagramação espacial e os atributos cosméticos do documento, promovendo a separação entre a camada estética e a árvore estrutural da informação.
  • III -O JavaScript opera como a camada de comportamento dinâmico e controle de fluxo interativo, viabilizando a reação síncrona ou assíncrona a eventos desencadeados pelo usuário sem a obrigatoriedade de recarregamento integral da página no navegador.

Quais estão corretas?

Gabarito Oficial: Alternativa (E)

Resolução e Fundamentação Técnica: O ecossistema de front-end assenta-se sobre o desacoplamento de responsabilidades entre estrutura, apresentação visual e comportamento dinâmico. O HTML atua como a infraestrutura elementar do documento, provendo hierarquia semântica e delineando a organização dos dados textuais e midiáticos da aplicação. O CSS atua de forma complementar, concentrando as definições cosméticas, responsivas e tipográficas, o que garante a uniformidade estética e o isolamento em relação à estrutura conceitual da página. O JavaScript desempenha a função de orquestração comportamental no ambiente do cliente, conferindo reatividade à página mediante escuta ativa e tratamento síncrono ou assíncrono de eventos disparados pelo usuário. Dessa forma, ele viabiliza a mutação de estado e a reconstrução de fragmentos da interface gráfica em tempo de execução sem demandar uma nova requisição HTTP de recarregamento integral do documento ao servidor. Em decorrência do alinhamento técnico de todas as proposições apresentadas, constata-se a veracidade integral das afirmações I, II e III.

Questão 03 Arquitetura e Fundamentos do DOM

O Document Object Model (DOM) constitui uma das abstrações fundamentais da arquitetura de navegadores web modernos. Sobre a concepção estrutural e a operação do DOM no contexto da execução de scripts client-side, considere as seguintes afirmações:

  • I -O DOM representa uma modelagem hierárquica em memória mantida pelo navegador para refletir a estrutura de um documento HTML ativo.
  • II -Quaisquer alterações de propriedades estruturais ou estilísticas promovidas no DOM via código JavaScript refletem-se exclusivamente no ambiente em execução no cliente, não provocando a modificação persistente do arquivo HTML originalmente hospedado no servidor web.
  • III -A árvore de nós do DOM fornece uma interface programática unificada pela qual o código JavaScript é capaz de ler, injetar, alterar e remover nós, estilos e atributos do documento em tempo real.

Quais estão corretas?

Gabarito Oficial: Alternativa (E)

Resolução e Fundamentação Técnica: O Document Object Model consiste em uma interface de programação de aplicações (API) criada e mantida na memória volátil do navegador, que espelha as declarações do código-fonte em nós de objetos navegáveis e manipuláveis estruturados sob a forma de uma árvore hierárquica. Toda alteração arquitetural, cromática ou contextual exercida pelo motor JavaScript atua unicamente sobre essa representação volátil mantida no subsistema do navegador cliente, gerando impactos estritamente locais no tempo de vida da sessão. Por conseguinte, tais mutações são incapazes de transpor a camada do cliente para regravar o arquivo-fonte HTML estático armazenado fisicamente no servidor remoto. Ademais, a interface de manipulação do DOM oferece controle dinâmico para operações de leitura, mutação, inserção e deleção de elementos estruturais, atributos funcionais e propriedades de estilização, conferindo interatividade ampla à página. Logo, todas as afirmativas avaliadas (I, II e III) encontram-se rigorosamente corretas.

Questão 06 Regras de Sintaxe CSS no JavaScript

A respeito das regras sintáticas e conceituais que regem a manipulação de propriedades de estilo CSS por intermédio da interface de objetos style de elementos no JavaScript, considere as seguintes afirmações:

  • I -Propriedades de folha de estilo originalmente nomeadas segundo o padrão delimitado por hífens (kebab-case), a exemplo de font-size e background-color, são mapeadas no objeto style pela convenção camelCase, resultando respectivamente em fontSize e backgroundColor.
  • II -Valores que exprimem dimensões métricas ou escalares no CSS devem ser informados como literais do tipo cadeia de caracteres agregados de suas unidades (como "22px" ou "32px"), não sendo suficiente o envio de literais numéricos puros para a correta aplicação das diretivas de layout dependentes de dimensão.
  • III -A atribuição de valores a propriedades por meio do objeto style em tempo de execução invalida as classes declaradas no atributo class do HTML, forçando o navegador a suprimir permanentemente os estilos externos aplicados ao elemento.

Quais estão corretas?

Gabarito Oficial: Alternativa (C)

Resolução e Fundamentação Técnica: A manipulação de regras de estilização direta em elementos por intermédio da propriedade style exige a harmonização entre os padrões de sintaxe do CSS e do JavaScript. Como na linguagem JavaScript o símbolo de traço (-) atua como operador aritmético de subtração, a especificação do DOM mapeia as propriedades CSS nativamente nomeadas em notação kebab-case para a convenção camelCase. Desse modo, propriedades compostas como font-size e background-color transformam-se, respectivamente, nas propriedades de objeto fontSize e backgroundColor. Paralelamente, os atributos de estilo dimensionais demandam uma unidade métrica CSS expressa em uma cadeia de caracteres (por exemplo, "22px" ou "32px"), sendo ignoradas ou invalidadas eventuais atribuições escalares desprovidas de unidade métrica. Por fim, a terceira afirmação mostra-se errônea, dado que a mutação direta do objeto style opera como estilo em nível de nó (inline style), mantendo a integridade das classes aplicadas e sobrepondo-se a elas unicamente no âmbito de especificidade em cascata, sem que haja supressão das definições estéticas estruturadas em arquivos externos. Apenas as afirmações I e II mostram-se corretas.

Questão 07 Eventos e addEventListener

No contexto da programação orientada a eventos no navegador, a captura e o tratamento de interações do usuário sobre a interface gráfica são comumente operacionalizados via addEventListener. Acerca da estrutura, sintaxe e funcionamento do método addEventListener, assinale a alternativa correta:

Gabarito Oficial: Alternativa (A)

Resolução e Fundamentação Técnica: O modelo moderno de controle e tratamento de eventos fundamenta-se no registro explícito de observadores (listeners) por intermédio da interface unificada EventTarget.addEventListener(). Essa função demanda em sua assinatura primordial o envio de uma cadeia de texto descritiva do tipo do evento sem o prefixo histórico on (sendo, por conseguinte, empregado "click", e não "onclick"), associada a uma função executável (callback) encarregada de recepcionar o evento e deflagrar a lógica programática correspondente. Diferente de atribuições diretas de propriedades de nós legadas, a abordagem por addEventListener não sobrescreve ouvintes anteriormente vinculados ao mesmo elemento, permitindo coexistência e múltiplos tratamentos concorrentes. Além disso, tal funcionalidade é compartilhada por todos os objetos herdados da classe Node, incluindo divisões estruturais, títulos, campos textuais e o próprio objeto document, afastando a alegação restritiva de aplicabilidade unicamente sobre elementos <button>.

Questão 08 Execução Sequencial e Mutação Cumulativa

Considere o fragmento de código integrado contendo trechos de marcação HTML e lógica em JavaScript:

<h1 id="titulo">Texto Padrão Inicial</h1>
<div class="grupo-botoes">
    <button type="button" id="btn-sucesso">Sucesso</button>
    <button type="button" id="btn-alerta">Alerta</button>
    <button type="button" id="btn-urgente">Urgente</button>
</div>
const titulo = document.getElementById("titulo");
const botaoSucesso = document.getElementById("btn-sucesso");
const botaoAlerta = document.getElementById("btn-alerta");
const botaoUrgente = document.getElementById("btn-urgente");

botaoSucesso.addEventListener("click", function() {
    titulo.innerText = "Tudo Certo! Operação Concluída.";
    titulo.style.color = "#16a34a";
    titulo.style.fontSize = "22px";
});

botaoAlerta.addEventListener("click", function() {
    titulo.innerText = "Atenção: Verifique os Campos!";
    titulo.style.color = "#ea580c";
    titulo.style.fontSize = "20px";
});

botaoUrgente.addEventListener("click", function() {
    titulo.innerText = "ERRO CRÍTICO NO SISTEMA!";
    titulo.style.color = "#dc2626";
    titulo.style.fontSize = "26px";
});

Considere que um usuário efetua o carregamento padrão da referida página em um navegador moderno e, na sequência estrita de uso, clica uma vez sobre o botão "Sucesso" e, logo em seguida, clica uma vez sobre o botão "Urgente".

Assinale a alternativa que apresenta com precisão o estado visual final dos atributos de texto, coloração e tipografia do elemento <h1> ao término das ações descritas:

Gabarito Oficial: Alternativa (B)

Resolução e Fundamentação Técnica: A análise sequencial do ciclo de despacho de eventos denota que o primeiro evento desencadeado a partir do clique sobre o botão "Sucesso" promoveu a redefinição pontual do elemento <h1>, ajustando o valor de innerText para "Tudo Certo! Operação Concluída.", a cor tipográfica para #16a34a e o corpo de fonte para "22px". Entretanto, a posterior ação deliberada do usuário, ao clicar imediatamente sobre o componente "Urgente", acionou a função anônima registrada no manipulador do terceiro botão. As instruções ali presentes reatribuíram o conteúdo textual para "ERRO CRÍTICO NO SISTEMA!", redefiniram a cor da propriedade color para #dc2626 e expandiram o corpo da fonte para a escala de "26px". Dado que a atribuição de propriedades a nós do DOM é executada de modo determinístico e cumulativo, as propriedades alteradas em um instante posterior sobrescrevem os valores definidos pelo gatilho antecedente. Desse modo, o estado final exposto ao usuário compreende o texto "ERRO CRÍTICO NO SISTEMA!", a coloração #dc2626 e a métrica de tamanho equivalente a 26px.

Questão 10 Falhas de Referência Nula (TypeError)

Considere a seguinte estrutura de documento web:

<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>Exemplo de Renderização</title>
    <script>
        const elemento = document.getElementById("titulo");
        elemento.innerText = "Novo Texto Injetado";
    </script>
</head>
<body>
    <h1 id="titulo">Texto Padrão Inicial</h1>
</body>
</html>

Ao processar o código supramencionado de forma síncrona, estrita e sem a utilização de atributos de diferimento (defer ou async) no elemento de script, o comportamento manifesto pelo navegador consistirá em:

Gabarito Oficial: Alternativa (B)

Resolução e Fundamentação Técnica: O navegador analisa o documento HTML sequencialmente de cima para baixo. Ao posicionar o elemento <script> no interior do <head> sem atributos que adiem sua execução (tais como defer ou async), o motor de renderização interrompe o parsing do documento para executar imediatamente o bloco de código. Nesse instante, o corpo da página (<body>) e o elemento <h1 id="titulo"> ainda não foram processados nem inseridos na memória como nós do DOM. Em decorrência dessa ausência, a chamada document.getElementById("titulo") falha em encontrar qualquer elemento associado e retorna o valor primitivo null. Na instrução subsequente, quando o interpretador tenta atribuir um valor à propriedade innerText sobre uma referência nula (null.innerText = ...), ocorre uma quebra de fluxo síncrona decorrente do lançamento de uma exceção irrecuperável de tipo (TypeError: Cannot set property 'innerText' of null ou formato correlato no motor do navegador). Esse erro interrompe a execução do script e deixa o elemento <h1> com seu texto original intacto quando for finalmente processado pelo parser.
